① حالة المشروع والـPRs

منفّذ في الكود (بانتظار النشر): أمان P1/P2 + دمج التسعيرة P3 + تحصين تقارير الطالب ضد #REF!.

يحتاج إضافة (طلباتك الجديدة): ميزات منصّتي الطالب والمعلم أدناه — جديدة وتُنفَّذ عبر الجلسات.

② سير العمل لكل جلسة (٨ خطوات)

  1. افتح الجلسة من جذر المشروع، أول رسالة /init.
  2. الصق أمر العمل (من الأقسام أدناه).
  3. اطلب وضع الخطة (Plan) أولاً — لا تعديل قبل اعتماد الخطة.
  4. راجع الخطة → اعتمدها.
  5. ينفّذ Claude Code في مشروع واحد ويفتح فرعاً + PR.
  6. راجع الـPR (أو اطلب مني مراجعته في Cowork).
  7. ادمج الـPR → من Operations: clasp push + New version (نفس Deployment ID)؛ الواجهة تُنشَر تلقائياً.
  8. تحقّق: ?action=health + اختبار وظيفي على الصفحة.

③ المودِل المناسب

  • تصميم/منطق معقّد متعدّد الملفات (المهام التلقائية، الإشراف الأسبوعي، إعادة هيكلة إدارة المهام): استخدم Opus + Plan mode.
  • إصلاحات واجهة مباشرة (عرض الجدول، الأيقونات، النوافذ المنبثقة): Sonnet كافٍ وأوفر.
  • توثيق/تعديلات صغيرة: Sonnet/Haiku.

⑤ أوامر منصّة المعلم — إدارة المهام

هذه إعادة تصميم مترابطة. نفّذها على مرحلتين: المنطق/البيانات (Core System) ثم الواجهة (Frontend). كلها على نفس صفحة الويب ونفس الشيت.
T1+T2 — «كل المعلمين» + حضور الاجتماع الذكي CoreFrontend · Opus
/init  — المشروع: teacher (+ frontend/teacher). خطة أولاً.
المطلوب في صفحة إدارة المهام / تعيين مهمة:
1) أضف خيار «كل المعلمين» عند تعيين المهمة (مثال: اجتماع للجميع).
   فعّله فقط لدور الوكيل/المدير (الصلاحيات).
2) تدفّق حضور الاجتماع: عند إنشاء مهمة «اجتماع لكل المعلمين»،
   اجعل الافتراضي «حاضر» لكل المعلمين تلقائياً، وواجهة المشرف
   تسجّل فقط «الغائبين» بالتأشير عليهم، والبقية تبقى «حاضر» آلياً.
3) خزّن النتيجة في نفس شيت المهام (عمود حالة لكل معلم).
تحقّق: أنشئ اجتماعاً تجريبياً وأشّر غائباً واحداً وتأكّد من الباقي حاضر.
T6+T8 — تأكيد الإنجاز + الأرشفة CoreFrontend · Opus
/init — المشروع: teacher (+ frontend/teacher). خطة أولاً.
المطلوب:
1) زرّ «تأكيد إنجاز» للمشرف/الوكيل على المهمة أو الاجتماع (مع توكن/صلاحية).
2) بعد التأكيد/التنفيذ، تنتقل المهمة تلقائياً إلى قسم «الأرشيف» (حالة=منجز)
   مع إبقائها في نفس الشيت (عمود archived/حالة)، ولا تظهر ضمن النشطة.
3) واجهة أرشيف بسيطة قابلة للتصفية بالتاريخ/النوع.
تحقّق: أكّد مهمة وتأكّد من انتقالها للأرشيف واختفائها من النشطة.
T7 — تحسين «إجراءات» والنوافذ المنبثقة Frontend & UI · Sonnet
/init — المشروع: frontend/teacher. خطة أولاً.
المطلوب في عمود/قسم «إجراءات» بصفحة إدارة المهام:
- استبدل نص «(اختياري)» وأي نص إجراء برموز/أيقونات واضحة (تعديل/حذف/تأكيد/تفاصيل).
- اجعل النوافذ المنبثقة (Modals) احترافية وديناميكية ومتجاوبة RTL،
  بخيارات متوقّعة بحسب نوع المهمة (اجتماع/إشراف/مهمة عامة).
عرض فقط — لا تغيّر منطق الخادم. خطة ثم PR.
T3+T4+T5 — المهام التلقائية والتوقيتات Core + schedule · Opus
/init — المشاريع: teacher + schedule. خطة أولاً (هذه حسّاسة).
السياق: راجع docs/أوامر-العمل-للجلسات.html قسم «تحليل المنطق».
المطلوب — أصلح مولّد المهام التلقائية:
1) طابور الصباح: مهمة حضور واحدة لكل فصل، تُسنَد لمعلّم الفصل/الحصة الأولى فقط
   (معلمين فقط، لا طلاب)، عند «بداية الدوام».
2) إشراف الراحة: مهمة لكل صف/شعبة عند «وقت راحة هذا الصف» المحسوب من
   إعداد الجدول «☕ استراحة كل صف (بعد الحصة رقم)».
3) أضف إعداد «استراحة كل صف (بعد الحصة رقم)» لكل الفصول إن كان ناقصاً،
   واحفظه في إعدادات الجدول واعرضه.
4) «بداية الدوام»: يجب أن يُحفظ دائماً ويُعرض في صفحة الويب (إعداد ثابت).
تحقّق: فصل به إعداد راحة بعد الحصة 3 يولّد مهمته في توقيته الصحيح فقط.
T9 — الإشراف الأسبوعي المتكرّر Core System · Opus (تصميم أولاً)
/init — المشروع: teacher (+ schedule). ابدأ بـ«تحليل تصميم» قبل الكود.
المطلوب: نظام إشراف أسبوعي متكرّر على نفس الشيت ونفس صفحة الويب:
- جدول «إشراف» (يوم الأسبوع ← معلمون ← نوع الإشراف، مثل إشراف الراحة).
  مثال: السبت 2–3 معلمين، الأحد 3 آخرين… بالتناوب.
- مولّد يومي (Trigger) يقرأ إشراف «اليوم» وينشئ مهامه تلقائياً للمعلمين المعيّنين.
- يتكامل مع تأكيد الإنجاز (T6) والأرشفة (T8) وتوقيتات الراحة (T3).
سلّم خطة التصميم (نموذج البيانات + التدفّق) للمراجعة قبل التنفيذ.

⑥ تحليل المنطق (للحالات المعقّدة)

أ) المهام التلقائية الصحيحة (T3)

  • نوعان فقط: طابور صباح (لكل فصل، معلّمه، عند بداية الدوام) وإشراف راحة (لكل صف/شعبة، عند راحته).
  • توقيت الراحة = من إعداد الجدول «استراحة كل صف (بعد الحصة رقم)» + تواقيت الحصص → لا توقيت موحّد للجميع.
  • لا تُنشأ مهام طلوع/نزول طلاب على المعلمين خطأً — المهام للمعلمين فقط.

ب) الإشراف الأسبوعي المتكرّر (T9)

  • نموذج بيانات: ورقة إشراف_أسبوعي: day_of_week, teacher, duty, after_period/time, active.
  • مولّد يومي يقرأ صفوف «اليوم» وينشئ مهام في نفس شيت المهام (FIFO، بلا تكرار عبر مفتاح يوم+معلم+نوع).
  • المشرف يؤكّد الإنجاز (T6) → أرشفة (T8). تقرير أسبوعي اختياري لاحقاً.

ج) ربط الحجب بالمعلم والصلاحيات

  • block_percentage (الاعدادات) → is_blocked للطالب → تظهر للمعلم حالة «محجوب» وتُقيّد عرض الدرجات حسب السياسة.
  • الصلاحيات (دور المدير/الوكيل) تتحكّم بـ: تعيين «كل المعلمين»، تأكيد الإنجاز، ضبط نسبة الحجب، إدارة الإشراف الأسبوعي.
  • أعد احتساب is_blocked تلقائياً بعد تحديث الرسوم (recomputeBlocks) لاتساق المنصّتين.
