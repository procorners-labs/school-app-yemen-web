٠ كيف تُستخدم هذه الصفحة

هذه الصفحة هي المرجع المعتمد الذي يوجّه عمل Claude Code (المسؤول عن تنفيذ إصلاحات الكود) ويُسجّل توجيهات Claude (المساعد التشغيلي). قبل أي تعديل: اقرأ CLAUDE.md ثم هذه الصفحة، والتزم بالثوابت في القسم ١.

توزيع الأدوار: Claude (التوجيه/التدقيق) يحدّد ماذا ولماذا وأين ويراجع المخاطر · Claude Code (التنفيذ) يطبّق التعديل بصياغة المشروع، مشروعاً واحداً، ثم يتحقق · المالك يوافق صراحةً على كل تغيير وينفّذ النشر.

١ الثوابت الحاكمة (إلزامية)

١) لا تعديل بدون إذن صريح لكل تغيير على حدة.
٢) صياغة الخلفية ES5 فقط: var فقط، دوال عادية، بلا دوال سهمية، بلا قوالب نصية (استخدم +).
٣) ثبات Deployment IDs: عند إعادة النشر استخدم New version لنفس الـDeployment فقط، حتى تبقى روابط /exec والـWorker صالحة.
٤) مشروع GAS واحد في كل مرة، والتحقق عبر ?action=health قبل الانتقال.
٥) فرع لكل تغيير + Pull Request، لا دفع مباشر للمنطق الكبير إلى main.
٦) لا تكسر التوافق: الواجهة تستدعي الخلفية عبر جسر gas-bridge.js (XHR/text-plain). أي دالة في whitelist.generated.json تستدعيها الواجهة فعلياً — لا تحجبها.

٢ نموذج الأمان (كيف يعمل)

كل مشروع GAS فيه ApiEndpoint.js بدالة doPost تستقبل {fn,args} وتنفّذ الدالة العامّة المطلوبة وفق:

  • حجب (denylist): تُمنع دوال الإطار (doGet/doPost/onOpen…)، الدوال الداخلية (تبدأ بـ _)، والدوال الخطرة في API_DANGEROUS_FUNCTIONS (مصدرها _build/denylist.generated.json).
  • طبقة ثانية: دوال *Protected تتحقق من توكن الجلسة بنفسها عبر validateMasterToken / ما يماثلها.
  • قاعدة الحجب: الحجب يمنع مسار الويب (doPost) فقط — الاستدعاءات الداخلية ومشغّلات Triggers تبقى تعمل. لذا حجب دالة لا يكسر المزامنة التلقائية.
قاعدة ذهبية: أي دالة عامّة تغيّر حالة أو تكشف سرّاً وليست مستدعاة من الواجهة → يجب أن تكون في الـdenylist. وأي دالة إدارية تستدعيها الواجهة → يجب أن تتحقق من التوكن (*Protected).

بوابة إنشاء المدارس (provisionNewSchool)

عامة بالتصميم (تسجيل ذاتي)، لكنها مُؤمّنة بـ: مفتاح دعوة إجباري متى كان مُعَدّاً + استثناء جلسة مالك مُصادقة. لتفعيل الحماية فعلياً يجب أن يعيّن المالك مفتاح دعوة من اللوحة (setInviteKeyProtected).

٥ صفحة التسعيرة — أين تشتغل وكيف تُربط

المكان المناسب: صفحة عامة لتسويق اشتراكات المدارس — تُربط من (أ) الموقع الرئيسي كزرّ تنقّل/دعوة لإجراء، و(ب) master-admin قرب تجديد الاشتراك renewSubscriptionProtected.

٧ التحقق بعد النشر

  • صحة المنصّات: افتح <exec>?action=health لكل مشروع غُيّر.
  • إثبات الحجب: POST {"fn":"getMasterSetting","args":["invite_key"]} إلى master /exec → يجب «دالة غير مسموح بها».
  • البوابة: بعد تعيين مفتاح دعوة، تسجيل عام بلا مفتاح → يُرفض؛ والمالك من اللوحة → ينجح.
  • التسعيرة: افتح <worker>/pricing → تظهر الصفحة؛ و?action=deployments يحوي pricing.

٨ مسؤوليات Claude Code (تنفيذ الإصلاحات)

قبل البدء: git pull · أنشئ فرعاً git switch -c claude/<المهمة> · اقرأ CLAUDE.md + هذه الصفحة.
  • التزم ES5 في كل ملفات .js الخلفية، وبصياغة الملفات المجاورة.
  • عند إضافة/حجب دالة API: حدّث الملف و_build/denylist.generated.json أو whitelist.generated.json معاً (لا تترك انحرافاً).
  • لا تلمس معرّفات النشر ولا روابط /exec؛ أي دالة تستدعيها الواجهة (whitelist) لا تحجبها.
  • غيّر مشروعاً واحداً، وأضف خطوة تحقق (?action=health أو اختبار doPost) في وصف الـPR.
  • سجّل أي تغيير جديد في القسم ٣ من هذه الصفحة قبل إغلاق المهمة.
